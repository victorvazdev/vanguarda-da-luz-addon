# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Addon for **WoW Forever** (Interface 16001, modern Midnight 12.x API) for the guild "Vanguarda da Luz". It imports the event export string generated by the guild website, shows its own calendar, syncs data between guild members and sends raid alerts.

The addon does **not** write to the Blizzard calendar: in WoW Forever `C_Calendar.AddEvent()` is blocked for addon code (ADDON_ACTION_BLOCKED even from a click or `/run`). That automation was removed; don't reintroduce it without new evidence the API allows it. Code comments, docs and commit messages are in Brazilian Portuguese. UI text is written in Portuguese inside `L["..."]` and translated to English in `core/Locale.lua` (Portuguese on a `ptBR` client, English on any other); `tests/locale_spec.lua` fails if a used text has no English translation or a translation is unused.

## Commands

```bash
scripts/setup-dev.sh          # one-time: Lua 5.1 + LuaRocks in .lua/ (via hererocks in .venv/), busted, luacheck
scripts/check.sh              # luacheck VanguardaDaLuz tests + busted (what CI runs)
.lua/bin/busted tests/alert_spec.lua          # single spec file
.lua/bin/busted --filter "valida o texto"     # single test by name
.lua/bin/luacheck VanguardaDaLuz tests
scripts/package.sh            # dist/VanguardaDaLuz-<version>.zip (version from the .toc)
```

Tests must run from the repo root (they read `VanguardaDaLuz/...` and `docs/exemplos-addon/...` by relative path). CI (`.github/workflows/ci.yml`) runs luacheck, busted and the package script.

## Project rules

- **Never change the export string format** (`VDL1:<adler32>:<EncodeForPrint(deflate)>`, spec in `docs/formato-string-addon.md`, acceptance criteria in `docs/criterios-de-aceite.md`). It is produced by the website.
- If a spec is incomplete, contradicts the request, or the game API prevents something: stop and ask.
- Workflow: research and propose, wait for approval, then implement. Commit/push only when asked.
- Pure logic stays separate from UI and game API, and is tested with busted on Lua 5.1. luacheck must have zero warnings; new game globals go in `.luacheckrc` `read_globals`.
- Third-party libs live in `VanguardaDaLuz/libs/` with licenses and versions recorded in `libs/LIBRARIES.md`. Nothing may depend on internet access.
- Everything that depends on the game version goes in `core/Flavor_Forever.lua` (and the `.toc`), so a future `Flavor_Retail.lua` + `VanguardaDaLuz_Standard.toc` can reuse the rest.

- **Reverse string** `VDLP1` (addon → site, attendance) is specified in `docs/formato-string-presencas.md` with fixtures `docs/exemplos-addon/presencas*.{txt,lua}`. The site (`../vanguarda-da-luz-front`) keeps copies; keep both repos in sync on any change.

## Architecture

All files receive `local _, ns = ...` and attach a module to the shared namespace (`ns.Codec`, `ns.Comm`, ...). Load order is the `.toc` order, and modules only reference each other through `ns` at call time. **A new file must be added to `VanguardaDaLuz_Forever.toc`** — and, if it is pure logic, also to `FILES` in `tests/helpers/addon.lua`.

Layers (`VanguardaDaLuz/`):
- `core/` — `Locale` (`ns.L`, `ns.locale`, English table), `Init` (internal event bus `ns.On`/`ns.Fire` with `DATA_UPDATED`, `PENDING_UPDATED`, `CALENDAR_STATUS`, `SYNC_STATUS`; `ns.Print`), `Config` (all tunables), `Flavor_Forever` (version-specific API), `Main` (game events, `/vdl` commands; loads last).
- `logic/` — pure Lua, no game API: `Codec` (decode/validate the string), `Snapshot` (diff of a full export against stored events: created/updated/cancelled/removed/outside-window), `Import`, `Time` (Brasília UTC−3 vs. server offset), `Protocol` (addon messages), `Trust` (accepted ranks), `Alert`, `Attendance` (in-game RSVP store, last-writer-wins per event+character), `PresenceCodec` (`VDLP1` string), `Professions` (profession levels store, list rows/filter/sort, F/K payloads), `Members` (item level + main/alt store, M/O payloads, row/tooltip text), `Roster` (members list rows/filter/sort), `Together` (time played with guildmates: counting rule, max-wins store, per-person totals with alts summed into the main, ranking, T/V payloads), `Text` (UTF-8-safe helpers).
- `game/` — glue to the game API: `Store` (SavedVariables `VanguardaDaLuzDB`), `Guild` (roster, `CheckSender` refreshes roster once before deciding), `Comm` (AceComm on `GUILD`, prefix `VanguardaDaLuz`), `Warning` (raid alert), `Presence` (RSVP toggle, sync, `VDLP1` export), `GuildProfessions` (own professions announce, relay, rows), `GuildMembers` (own item level + account main announce, relay; `/vdl main`), `GuildTogether` (60 s ticker: in group with a connected, non-AFK guildmate in the same zone — members found by GUID in the roster — adds a minute; announces every 10 min).
- `ui/` — `Theme` (colors/fonts copied from the website tokens; build all widgets with its helpers), reusable panels (`HomePanel` (MOTD/guild info with copyable links, next event), `CalendarPanel` with `wide`/`compact` layouts, `ProfessionsPanel`, `MembersPanel` (roster + item level/main, sortable headers), `AdminPanel`, `SettingsPanel` (main, minimap, guild-window feature toggles via `Store.GuildFeature`/`SetGuildFeature`, event `SETTINGS_UPDATED`); created with `Create(parent, width, ...)`, the host calls `panel:Refresh()` while visible) and the frames that host them: `MainFrame` (tabs Início/Eventos/Profissões/Membros/Administração/Configurações, always opens on Início), `ProfessionsFrame` and `GuildTabs` (Eventos/Profissões/Administração tabs added to Blizzard's `CommunitiesFrame`: own CheckButtons below `GuildInfoTab`, an overlay over the content area, only `HookScript` on Blizzard frames — never hide/replace them; frame names in `Flavor.guildWindow`; when Blizzard's Informações or Membros tab is checked the overlay shows `HomePanel` / `MembersPanel` with a "Ver original da Blizzard" button — `COVERS` in `GuildTabs`) and `GuildRoster` (own FontString + tooltip line on each member list row via `hooksecurefunc` on `SetMember`, mixin and existing rows).

Key cross-cutting behavior:
- **Guild gate:** everything (calendar, import, sync, alerts) requires `Guild.IsMember()` — in a guild named exactly `Config.GUILD_NAME`. Anyone else (no guild or another guild) only gets `ui/WelcomeFrame` with the Discord link; `MainFrame.Toggle`, `ImportDialog.Show`, `AlertDialog.Show` and the slash handler redirect there. Guild info loads late after login, so the login sync request waits for `PLAYER_GUILD_UPDATE`/`GUILD_ROSTER_UPDATE`.
- **Trust:** only the Guild Master (rank index 0, named "Grão Lorde") and rank name "Lorde" (`TRUSTED_MAX_RANK_INDEX` / `TRUSTED_RANK_NAMES` in `Config`) may broadcast data or send alerts; receivers verify the sender's rank in the roster before accepting.
- **Sync protocol** (`logic/Protocol.lua`): `Q|n` query on login after a random delay, `H|n` announce, `D|n|raw` full original string (receivers re-validate checksum), `A|id|text` raid alert, `P|event|1or0|t` own RSVP, `R` RSVP request (sent with `Q`), `L|VDLP1…` known RSVPs (any member answers), `F|t|list` own professions+levels, `G` levels request, `K|list` known levels (any member answers) — kept for old versions; new versions send `J|t|list` (with profession IDs) alongside `F`, request with `Y` (sent with `Q`) and answer `Y` with `X|list`, `M|t|data` own item level+main, `N` request (sent with `Q`), `O|list` known (any member answers), `T|seconds` own time with guild, `U` request (sent with `Q`), `V|list` known. Only trusted members with newer data answer, after a random delay, cancelled when someone else announces the same or newer.
- **Messaging lockdown** (boss encounters, M+, PvP): `Comm` queues the last message of each kind and resends on `ADDON_RESTRICTION_STATE_CHANGED` or a 30 s ticker; alerts are refused instead of queued.
- **Professions:** `C_Club.GetMemberInfo` gives every member's primary profession names and IDs (`profession1ID`, and presence), but `profession*Rank` is always 1 in WoW Forever, so levels come from each member's addon (`GetProfessions`/`GetProfessionInfo`, 7th return = the same skill-line ID), announced and relayed. Match levels to club professions by ID (names change with the game language), falling back to name for data from old versions.
- **Item level / main-alt:** only the own item level is readable (`GetAverageItemLevel`, equipped value), so each addon announces it. The main is per account (`db.settings.main`, set with `/vdl main`); other characters of the account in the guild announce themselves as alts of it. Guild info editing (`SetGuildInfoText`) is blocked for addons in WoW Forever (confirmed), so the Informações overlay keeps a button to the original.
- **Player names** in WoW Forever: `UnitName("player")` returns first name + surname (the surname sits where Retail has the realm), while roster and addon-message senders use `"First Surname"` with a space. Resolve the player's own name from the roster by GUID (`Guild.PlayerName`/`Guild.IsPlayer`); don't strip at spaces.

## Tests

- `tests/helpers/addon.lua` loads the pure logic into a fresh `ns` per call; specs use `docs/exemplos-addon/` fixtures (`valida.txt`, `corrompida.txt`, `esperado.lua`).
- `tests/smoke/run.lua` loads the whole addon in `.toc` order with a minimal mocked game API and drives import, sync and alerts via slash commands and button clicks (`Click(label)` finds buttons by text); `C_Calendar` is nil there on purpose. `smoke_spec.lua` asserts on its printed output. When adding UI or game calls, extend the mocks there.
- What can only be verified in the game is listed in README "Roteiro de teste no jogo" — update it when adding behavior that depends on unconfirmed API.
